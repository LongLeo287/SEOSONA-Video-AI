# 📜 Standard Procedure (SOP): SEOSONA VIDEO CREATION

This document specifies the standard data processing flow (Input/Output) for the entire SEOSONA Video System, strictly following the SEOSONA OS operating system philosophy.

## 1. Workspace
Each video project must be in a separate space at `8_WORKSPACE/<project_name>`.
Absolutely prohibit writing files outside the project directory or creating random temp folders outside `.temp`.

Standard structure of a project (automatically generated by `project_generator.py` or `4_BRAIN/video_engine.py` → `native_composer.py`):
```text
8_WORKSPACE/<ProjectName>/
├── <ProjectName>.mp4 → Main video
├── SRT/<ProjectName>.srt → Subtitles
├── Thumbnail/<ProjectName>_Thumbnail.png → Cover image
├── Bao_cao_chat_luong.md → Quality score and ML feedback
└── .temp/ → Temp files (voice.mp3, hf_render/)
```

### Self-Cleaning & Rollback Mechanism
To prevent empty duplicate folders and workspace clutter, the system strictly enforces a **"No Zombie Folders"** rule. If a pipeline crashes (e.g. TTS API failure, script validation rejection by OODA Loop) before the final `.mp4` and `.srt` files are generated, the system will automatically **delete** the incomplete project folder during the Exception handling phase.

## 2. Input Standards
- **Script:** Only accepts utf-8 text. Required to go through `_apply_lexicon_filter` to Vietnameseize borrowed English words before calling TTS.
- **Parameters (Params):** `brand`, `mode`, `aspect_ratio`.

## 3. Output Standards
- **Video:** The main `.mp4` file is generated by HyperFrames and output to the root of the project directory `8_WORKSPACE/<ProjectName>/`.
- **Database:** Any rendering operation (success/failure) must be logged by `db_manager.py` to `video_os.db`.
- **Machine Learning Analytics:** All productions are routed through the `EVALUATE_NODE`. The system outputs a machine-readable JSON post-mortem to `3_MEMORY/reports/` and a human-readable `Bao_cao_chat_luong.md` into the workspace.

## 4. Quality Control & OODA Loop
- **OODA Auto-Correction:** During production, if a scene exceeds the maximum word count or fails design rules, the `editor.py` will trigger the OODA Loop to automatically rewrite or trim the script (up to 3 retries) before passing it to HyperFrames.
- **Scoring:** `4_BRAIN/quality_scorer.py` evaluates the final output based on brand constraints (e.g. 9:16 aspect ratio, valid colors, clear audio).

## 5. Responsibilities of Agent (Orchestrator)
It is the responsibility of the Orchestrator Agent to read this SOP carefully before scheduling and coordinating Skills. All file paths passed to Skills (TTS, Whisper, HF) must comply with the canonical output structure defined in MASTER_OPERATION.md (`.temp/`, `Thumbnail/`, `SRT/`).
