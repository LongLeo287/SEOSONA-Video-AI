**Full transcript spine:** "Một cách để tiếp cận khách hàng dễ hơn là show kỹ năng từ những video bạn edit… hôm nay Khánh chia sẻ các Raw luyện tập để bạn có thể thực hành và build [portfolio]…"

**Why this reel matters for the build:** it is the single best reference for TWO features we don't have yet — (1) the **device-mockup proof hook** (a real phone/DM screenshot floated as a 3D-tilted object in frame 0) and (2) **deliverable-as-object cards** — product thumbnails that materialize above the speaker's open palm and then collapse into a single folder icon. It also demonstrates the **section-pill caption** (frame 12) and the **two-color caption** convention used across the whole channel.

> Palette note: source uses a **green** spill/glow key light + green accent type. Our brand is LIGHT (blue #2A5BDA, coral #E2724D, green #16A34A, amber #D97706). We translate the *meaning* of the green (freshness / "new / go / positive") to our green ROLE, NOT the neon source hue. Card tints (purple/blue/amber) map to ROLE colors, not literal copies.

## 2. FRAME-BY-FRAME TIMELINE (per zone, per beat)

### BEAT A — Proof hook (frames 1–3, 0.0–6.0s)
- **TOP:** empty until 4.6s, then a headline card slides in on the RIGHT of the phone: "Những sản phẩm **tốt nhất** trên Profile **của bạn!**". Multi-line, left-aligned, ~55% down. Two-color: brand-green key phrases, white connectors.
- **MIDDLE (the object):** a **phone device-mockup** is the hero. Frame 1 it is upright & centered showing a DM thread (proof = a real inbound client message). Frames 2–3 it **rotates into a 3D tilt** (≈ -15° Y, +8° Z) and scroll-animates through the profile → product grid. A **dashed rounded-rect highlight ring** (green) + a **finger-tap cursor glyph** call out the grid — this is the "look at my portfolio" moment.
- **BOTTOM:** the DM text ("Hello! I really like your products…") is *inside* the mockup, not a separate caption. No karaoke line yet.
- **Motion:** phone entrance = scale-up + subtle float; tilt is a continuous ease. Green rim-light glow behind phone.

### BEAT B — Deliverable-as-object cards (frames 4–7, 6.0–13.0s)
- **TOP:** 2-line headline, **sequential swap** each ~1.8s (frames 4→5→6→7): "BẠN CẦN CÁC / CÁI RAW" → "KỸ NĂNG CỦA MÌNH / Ở TRONG ĐÓ" → "KHÁNH SẼ CHIA SẺ / CÁC CÁI RAW" → "CHO CHÍNH BẠN!". Same anchor position (~48% down, centered), only text content changes → this is a `header` card being re-fed sequentially, NOT four separate cards.
- **MIDDLE (the objects):** THREE portrait thumbnail tiles appear in a horizontal row, centered, sitting in the lower-mid zone **directly above the speaker's open upturned palm** (deliverable-into-hand metaphor). Each tile:
  - Rounded-corner portrait card (~9:16 mini), thin light border, drop shadow.
  - Distinct **color tint/gradient overlay**: Raw 1 = purple/magenta, Raw 2 = blue/cyan, Raw 3 = amber/gold (variety cue).
  - White label centered on lower third: "Raw 1", "Raw 2", "Raw 3".
  - Light smoke/particle wisp beneath (magic-reveal flourish).
  - At 10.1s the 3 cards **collapse/morph into a single yellow folder icon** with a thumbnail peeking from the top flap + caption "**20+ Raw Footage**" — three items → one deliverable. This morph is the payoff.
- **BOTTOM:** no karaoke; the headline carries the words.

### BEAT C — Kinetic title slate (frames 8–10, 13.0–18.5s)

## 3. CAPTION SYSTEM (channel convention, confirmed here)
- **Placement:** BOTTOM-CENTER but raised to ~vertical 52–58% (over the chest/mic, NOT screen-bottom), so it never collides with the app UI safe-zone. Single or two lines.
- **Two-color rule:** the **emphasized clause = brand green**, the **connective/neutral clause = white**. Which line is green alternates by meaning (the "payload" word gets the accent), e.g. #13 line-1 green, #14 line-2 green.
- **Type:** heavy condensed sans, all-caps, bold, tight leading, soft dark drop-shadow/edge-glow for legibility on the dark room.
- **Pill variant (#12):** single keyword in a horizontally-padded rounded-rect with translucent fill → our `section-pill`.

## 5. WHAT THE ENGINE CANNOT DO (flags)
1. **3D phone tilt with animated scroll** (frames 2–3) — ASS boxes are 2D; we can float a static tilted mockup PNG but not scroll-animate a live UI. **Mitigation:** pre-render the phone-scroll as a short `full`/`pip` B-roll clip, or ship a static tilted mockup with the dashed-ring + tap-cursor as separate ASS overlays.
2. **Card→folder morph** (frame 6) — ASS can't tween one shape into another. **Mitigation:** cross-fade (cards fade out + folder fades/pops in at same anchor) approximates the "collapse"; true morph needs a pre-rendered clip.
3. **Smoke/particle wisps** under cards — not an ASS primitive. **Mitigation:** overlay a looping particle PNG-sequence/webm as B-roll `pip`, or drop it.
4. **Objects tracking the moving hand** — the cards sit above the palm but the palm moves; source uses fixed screen anchors (cards don't literally follow the hand). We match by fixed anchor → **fine, no gap**, just don't promise hand-tracking.
5. **Staggered kinetic type reveal** on the slate — per-word timed entrance. If our `header`/slate only supports whole-card fade, we lose the stagger. **Mitigation:** either add per-line stagger to the slate renderer or accept a single fade.
6. **Device-mockup frame asset** — needs a bezel PNG library (phone frames) we don't yet have. **New asset dependency.**

## 6. PRIORITY — which engine GAP this reel best proves
1. **`object/thumbnail card` schema (deliverable-as-object)** — the headline feature; 3 tinted portrait tiles above the palm collapsing to a folder. Highest build value.
2. **`device-mockup` proof hook** — phone bezel + user proof screenshot floated as frame-0 hook.
3. **`section-pill`** (frame 12) — cheap, immediately reusable.
4. **`teaser-card` product slate** (frames 9–10) — full-B-roll launch announcement.
5. **caption two-color + raised placement** — already have; confirms convention.
